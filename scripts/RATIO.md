# 수시 경쟁률 — 쓰는 법

## 지금은 최종 경쟁률만 받습니다

접수가 끝났습니다. 접수 중의 실시간 경쟁률은 더 받지 않고, **대학이 올린 최종
경쟁률만** 받아 상담 보드에 붙입니다.

    ratio_final.py  →  data/ratio/board.json  →  board.html

저장소 폴더의 파일을 더블클릭하면 받기와 올리기를 이어서 합니다. **쓰시는 컴퓨터에
따라 파일이 다릅니다** — 배치 파일(`.bat`)은 윈도우 전용이라 맥에서는 눌러도 텍스트
편집기만 열립니다.

    윈도우   최종경쟁률.bat
    맥       최종경쟁률.command

하는 일은 둘이 똑같습니다. 맥에서 「확인되지 않은 개발자」라며 안 열리면, 파일을
**우클릭 → 열기**로 한 번만 열어 주시거나 터미널에서 `sh 최종경쟁률.command` 로
돌리시면 됩니다.

명령으로 돌리려면 (맥은 `python` 자리에 `python3`)

    python scripts/ratio_final.py     # 최종만 받아 data/ratio/board.json 에 쌓는다
    python scripts/ratio_upload.py    # 저장소에 올린다 (git 폴더면 git 으로 해도 됩니다)

### 주소는 어디서 구하나

- **유웨이 대학은 구할 것이 없습니다.** 최종이 뜨면 같은 주소의 표기가 「최종현황」으로
  바뀌므로, 돌릴 때마다 훑어보고 최종인 것만 담습니다. 아직 아니면 건너뛰고 다음에
  다시 봅니다.
- **진학어플라이 대학은 주소가 따로입니다.** 접수 중 보던 주소는 마감 시각에서 멈춰
  있고, 최종은 새 주소에 올라옵니다. 대학 입학처에서 최종 경쟁률 페이지를 여신 뒤
  주소창의 주소를 `scripts/ratio_final_urls.txt` 에 한 줄 더하시면 됩니다.
  대학 이름은 페이지가 스스로 말해 주므로 주소만 적으면 됩니다.

한 번에 다 구할 필요가 없습니다. 구하는 대로 더해 다시 돌리면 **이미 받아 둔 대학은
그대로 두고** 새것만 더합니다. 끝에 「아직 최종이 없는 대학」을 **우리 학생 지원 건수
순으로** 적어 주니 그 순서대로 구해 오시면 됩니다.

진학어플라이는 학교·집 인터넷에서만 열립니다(클라우드는 막혀 있어 채팅에서는 못 받습니다).

### 보드는 이 파일 하나만 봅니다

`data/ratio/board.json` 에는 **최종만** 들어갑니다. 보드는 그 값을 내보내기의
「경쟁률」 칸에 붙이고, 이름이 정확히 맞을 때만 붙입니다(`board/ratio.js`).
못 붙인 것은 내보내기 화면 위 「올해 최종 경쟁률」 판에 사유와 함께 나옵니다.

### 작년 표를 받아 오지 않도록 — 모집인원 대조

진학어플라이는 **작년 페이지도 그대로 열립니다.** 작년 것은 언제나 「최종」이라
적혀 있어서 표기만 보고는 가릴 수가 없습니다. 실제로 2027 조선대(11300581) 대신
2026 조선대(11300471)를 받아 담은 적이 있고, 그 바람에 카드의 모집인원과 경쟁률
표의 모집인원이 어긋나 보였습니다.

연도가 다르면 **모집인원이 어긋납니다.** 그래서 즐겨찾기의 모집인원을 잣대로 삼아
받아 온 표를 견줍니다. 올해 제대로 받은 32곳은 어긋난 모집단위가 **하나도**
없었고, 작년 표는 여럿 어긋났습니다.

    어긋남 0      그대로 담습니다
    어긋남 1      담되 한 줄 알립니다 — 모집인원 변경이나 입력 실수일 수 있습니다
    어긋남 2 이상  빼고 「올해 주소를 다시 구해 주세요」라고 말합니다

### 잣대 만들기

    python scripts/ratio_wanted_build.py 즐겨찾기.xlsx

즐겨찾기 엑셀(또는 csv)에서 **대학·모집단위·모집인원만** 뽑아
`scripts/ratio_wanted.json` 을 새로 씁니다. 이름·학번·반·번호·점수 칸은 **읽지도
않습니다.** 만들어진 json 에는 학생을 가리킬 수 있는 것이 하나도 없으므로 저장소에
두어도 됩니다. 엑셀 자체는 선생님 컴퓨터에만 두세요 — 저장소에 넣지 않습니다.

지원이 바뀌면(추가·취소) 엑셀을 새로 받아 이 명령을 다시 돌리면 됩니다. 같은 파일이
「아직 최종이 없는 대학」을 지원 건수 순으로 세는 데도 쓰입니다.

## 선생님 PC에서 한 번에 돌리기

윈도우는 저장소 폴더의 `경쟁률수집.bat`을 더블클릭합니다.
맥은 터미널에서 `sh 경쟁률수집.command`.

네 단계를 이어서 합니다: 수집 → 화면 만들기 → 내년용 자료로 접기 → 저장소에 올리기.

올리기는 폴더가 git 저장소면 git으로, ZIP으로 내려받은 폴더면
`scripts/ratio_upload.py`가 GitHub 토큰으로 직접 올립니다. 토큰은 처음 한 번만
묻고 사용자 홈 폴더의 `.univ_token`에 둡니다(저장소 폴더 밖이라 함께 올라가지
않습니다). 토큰을 채팅이나 코드에 적지 마세요.

토큰 만들기: github.com → 프로필 → Settings → Developer settings →
Personal access tokens → Fine-grained tokens → Generate new token.
Repository access 에서 `univ` 저장소만 고르고, Permissions → Contents 를
Read and write 로 두면 됩니다. 만료는 90일 정도로.

올리지 못해도 화면 파일은 정상이라 그대로 열립니다.

    python scripts/ratio_build.py       # 스냅샷 + 과거 자료 -> ratio.html · data/ratio/board.json

## 언제 돌려 두면 좋은지

내년 예측의 재료가 되는 건 **마감 사흘 전부터 마감 시각까지의 스냅샷**입니다.
과거 자료가 다섯 구간(3일 전·2일 전·1일 전·마감일 오전·마감일 오후)뿐이라,
올해는 그보다 촘촘히 남겨 두면 내년에는 시각 단위 예측이 가능해집니다.

권하는 간격:

| 시기 | 간격 |
|---|---|
| 마감 3일 전 ~ 2일 전 | 하루 두 번(오전·오후) |
| 마감 1일 전 | 두 시간마다 |
| 마감일 | 한 시간마다, 마감 두 시간 전부터는 30분마다 |
| 마감 뒤 | 「최종」이 뜬 뒤 한 번 더 |

윈도우 작업 스케줄러에는 `경쟁률자동.bat`을 겁니다(멈추지 않고, 브라우저를
열지 않고, `log\auto-날짜.txt`에 결과를 남깁니다). 명령 프롬프트에서 폴더 경로는
본인 것으로 바꿔서:

    schtasks /create /tn 경쟁률수집 /sc minute /mo 20 /st 08:00 /et 22:00 /k /tr "\"D:\경로\univ\경쟁률자동.bat\"" /f

20분마다 08:00부터 22:00까지 돌고 22:00에 멈춥니다(`/k`). 경로에 공백이나
괄호가 있으면 위처럼 `\"…\"`로 감싸야 합니다. 바로 한 번 시험은
`schtasks /run /tn 경쟁률수집`, 상태는 `schtasks /query /tn 경쟁률수집 /v /fo list`,
끝난 뒤 지우기는 `schtasks /delete /tn 경쟁률수집 /f`. PC가 잠들면 안 도니
전원 옵션에서 절전을 끄고, 토큰은 미리 한 번 손으로 돌려 저장해 둡니다.
직전 대비 증가(+숫자)는 한 시간 넘게 앞선 스냅샷과 비교하므로, 몇 분 간격으로
여러 번 돌려도 비교 대상이 흐트러지지 않습니다.

## 자동으로 올리기 — GitHub Actions

`.github/workflows/ratio.yml`이 유웨이 대학을 클라우드에서 스스로 수집해 올립니다.
**접수가 끝나 일정(schedule)은 주석으로 멈춰 두었습니다** — 내년 접수 기간에 풀면 됩니다.
Actions 탭에서 「ratio」→「Run workflow」를 누르면 바로 한 번 돌고, 접수 기간
(9월 7~11일) 한국 시각 9~21시 매시 정각에 스스로 돕니다.

다만 일정(schedule)은 **저장소의 기본 브랜치**에서만 돕니다. 지금 기본 브랜치는
`claude/busy-bohr-akL3s`라 이 브랜치에서는 손수 누를 때만 돕니다. 저장소 설정
→ Branches 에서 기본 브랜치를 이 브랜치로 바꾸면 일정대로 돕니다.

정리하면 자료가 들어오는 길은 셋입니다. 셋 다 결과는 같은 스냅샷 파일이라
섞여도 됩니다.

| 길 | 되는 대학 | 손 |
|---|---|---|
| 선생님 PC에서 `경쟁률수집.bat` | 유웨이 + 진학어플라이 | 더블클릭 (올리기까지) |
| GitHub Actions | 유웨이만 | 없음 |
| 채팅(Claude)에서 명령 실행 | 유웨이만 | 요청할 때마다 |

세 번째 길은 앞의 둘이 안 될 때의 예비로만 두시면 됩니다. 자료 작업을 채팅에서
이어 갈 필요는 없습니다.

## 예측이 어떻게 나오고 얼마나 맞는지

배율 = 최종 경쟁률 ÷ 같은 시점 경쟁률. 과거 3개년에서 이 배율을 모아 지금
경쟁률에 곱합니다. 두 갈래를 기하평균으로 합칩니다.

- **자리 배율**: 같은 모집단위 → 같은 대학·전형 → 같은 대학·유형 → 전형유형
  순으로 표본이 넉넉한 단계의 중앙값. 그 전형만의 막판 흐름을 압니다.
- **구간 배율**: 같은 시점에 경쟁률이 비슷했던 곳들(1 미만 · 1~2 · 2~3 · 3~5 ·
  5~10 · 10 이상)의 중앙값. 같은 대학 표본이 15개 이상이면 그 대학 것, 아니면
  같은 전형유형 것, 그것도 30개가 안 되면 전체 것.

구간 배율을 넣은 이유: 지금 낮은 곳일수록 막판에 크게 뜁니다. 마감 1일 전에
1:1 미만이던 곳은 최종까지 중앙값 3.0배, 10:1 넘던 곳은 1.65배였습니다.
자리 배율만 쓰면 낮은 곳의 최종을 4할 가까이 낮게 보고(예측÷실제 중앙 0.58),
상담에서 제일 중요한 「이 학과 정말 미달로 끝나나」를 계속 틀리게 됩니다.

빌드 때마다 자료의 앞선 두 해(2024·2025) 배율로 마지막 해(2026) 최종을 맞혀 보고
그 결과를 화면 아래 「이 예측이 얼마나 맞는지」 표에 그대로 적습니다. 현재 값:

| 시점 | 중앙 오차 | 80% 구간 적중 |
|---|---|---|
| 3일 전 | 25% | 81% |
| 2일 전 | 21% | 79% |
| 1일 전 | 15% | 80% |
| 마감일 오전 | 8% | 79% |
| 마감일 오후 | 6% | 75% |

「최종 2:1 미만」 확률은 배율을 옮기지 않은 구간 표본에서 곧바로 셉니다
(같은 시점에 경쟁률이 비슷했던 곳 중 실제로 2:1 미만으로 끝난 비율).
역검증에서 70%대로 적힌 곳은 실제 58~69%, 90%대는 80~87%가 그렇게 끝났습니다.
조금 부풀려 보이니 90% 이상만 「거의 확실」로 읽는 편이 안전합니다.

## 70%컷 · 내 등급 · 상담 추천순

`data/ipgyeol.json`의 가장 최근 해 70%컷을 모집단위마다 붙입니다. 전형이 맞으면
그 값, 아니면 같은 유형(교과/종합)의 중앙값을 회색으로 보입니다. 화면의
「내 등급」은 메모리에만 있고 저장하지 않으며, 새로 고치면 지워집니다.
학생 이름을 넣을 곳은 없습니다.

「상담 추천순」은 최종 2:1 미만 확률 45 · 예측 최종 20 · 진도율 15 · 2025 동시점
대비 10 · 근거의 두께 10으로 100점을 만들고, 등급을 알면 닿지 않는 곳(컷보다
0.3등급 넘게 모자람)을 40점 내리고 여유를 15점까지 보탭니다. 이 정렬을 고르면
행마다 근거가 적힙니다.

## 화면

검색은 대학·전형·모집단위·단과대를 함께 보고, 공백·가운뎃점·괄호를 무시합니다.
띄어쓴 말은 모두 만족(「전남대 간호」), 「-농어촌」은 빼기, 자음만 치면 초성 검색.
필터는 지역(입결 자료의 구분) · 대학 · 전형 유형 · 계열 · 최소 모집인원 · 지역인재만 ·
내 등급 · 지금/최종/작년/거르기 체크.

교사용 데스크톱 도구가 기본이고, 640px 이하(폰)에서는 표 대신 한 행을 한 장으로
그리는 목록으로 바뀝니다. 같은 필터·정렬·즐겨찾기를 씁니다. 표 머리줄은 표
상자 안에서 고정되고, 첫 열(대학)은 옆으로 밀어도 남습니다.

## 상담 보드로 이어 붙이기

수집한 경쟁률은 상담 보드(`board.html`)의 내보내기에서 「경쟁률」 칸을 스스로 채웁니다.
수집을 한 번 돌리면 `data/ratio/board.json` 이 함께 만들어지고, 보드가 그 파일을
읽습니다. 따로 하실 일은 없습니다.

**정확히 맞을 때만 붙입니다.** 대학·전형·모집단위 이름이 모두 맞고, 그 전형에 그
이름의 줄이 하나뿐일 때만 씁니다. 닮은 이름을 고르지 않습니다 — 옆 전형의 숫자가
붙으면 종이에 틀린 숫자가 실리고, 어디에도 틀렸다고 적히지 않기 때문입니다.
못 붙인 것은 내보내기 화면 위 「올해 최종 경쟁률」 판에 학생·대학·사유까지 한 줄씩
나옵니다. 그 목록만 카드에서 손으로 적어 주시면 됩니다.

모집인원이 즐겨찾기와 다른 줄은 붙이되 그 판 맨 위에 따로 모읍니다. 접수 중에 인원이
조정되면 그렇게 어긋납니다. 양쪽 인원을 나란히 적어 두니 아닌 것만 카드에서 지우시면
됩니다.

**「최종」이라 뜬 뒤의 값만 종이에 실립니다.** 접수 중에 받아 둔 잠정 경쟁률은
화면의 「아직 최종이 아닌 곳」에만 모입니다. 대학이 최종을 올린 뒤 수집을 한 번 더
돌리면 그 자리가 저절로 찹니다.

이어 붙지 않는 자리는 이렇습니다.

| 왜 | 어떻게 되나 |
|---|---|
| 전형 제목을 못 읽는 페이지(동국대) | 그 대학은 통째로 빠집니다 |
| 한 번 수집한 것에 같은 이름의 페이지가 둘(홍익대 서울·세종) | 캠퍼스를 못 가려 빠집니다 |
| 학과 여럿을 쉼표로 묶어 한 줄에 적은 계열모집(조선대) | 그 줄은 한 학과의 숫자가 아니라 뺍니다 |
| 즐겨찾기의 전형명이 덜 구체적일 때(「종합(SSU미래인재)」 ↔ 서류형·면접형) | 어느 쪽인지 몰라 비웁니다 |

## 최종 경쟁률은 주소가 따로입니다 — 넣는 법

진학어플라이는 마감 뒤 최종 경쟁률을 **다른 주소**에 올립니다. 접수 중에 보던 주소는
마감 시각의 숫자에서 멈춰 있고, 거기서는 최종이 나오지 않습니다.

대학 입학처에서 최종 경쟁률 페이지를 여신 뒤, 주소창의 주소를 그대로 붙여 넣으세요.

    python scripts/ratio_final_add.py "https://addon.jinhakapply.com/RatioV1/RatioH/Ratio10080381.html"

여러 곳을 한꺼번에 넣으려면 메모장에 한 줄에 하나씩 적어 두고

    python scripts/ratio_final_add.py --file 최종주소.txt

어디 것인지는 알아서 가립니다 — 진학어플라이·유웨이·그 밖의 주소. 진학어플라이는
코드 8자리만 적어도 되고, 같은 것을 두 번 넣어도 한 번만 남습니다. 넣고 나서
`경쟁률수집`을 한 번 돌리면 됩니다.

**최종 주소에서 온 페이지는 글자를 보지 않고 최종으로 칩니다.** 선생님이 최종 자리에
주소를 적어 둔 것 자체가 근거입니다. 실시간 주소와 최종 주소를 함께 받으면 같은 대학이
두 장이 되는데, 그때는 최종 쪽을 씁니다.

지우려면 `scripts/ratio_sources.json` 의 `uway_final` · `jinhak_final` · `other_final`
목록에서 그 줄을 지우면 됩니다.

## 진학어플라이는 「최종」을 스스로 못 읽습니다

유웨이는 최종이 뜨면 페이지 표기가 「최종현황」으로 바뀌고, 그걸 그대로 읽습니다 —
9월 11일 18시 35분 기준으로 경북대 · 고려대(서울) · 광운대 · 서울시립대 · 한국외대가
그렇게 바뀌었습니다.

진학어플라이는 다릅니다. **기준시각 표기 자체가 안 잡힙니다.** 9월 10일 18시 수집에서
딱 한 번 「최종」이라는 글자를 읽은 뒤로는 스물네 번 내리 빈 값입니다. 최종 판정은
「기준시각에 최종이라는 글자가 있는가」로 하므로, 이대로면 진학어플라이 대학은
**최종으로 바뀌지 않습니다.** 우리 학생 302건이 걸린 38곳이 여기에 해당합니다.

그래서 **주소로 가립니다.** 위의 「최종 경쟁률은 주소가 따로입니다」대로 최종 발표
주소를 넣어 주시면 글자를 읽지 않고 최종으로 칩니다.

글자로도 읽게 고치고 싶으면 마감 뒤의 페이지 원본이 필요합니다. 클라우드에서는 403이라
받을 수 없으니 선생님 PC에서 한 번 받아 주세요.

    python scripts/ratio_fetch.py --raw-dir

`data/ratio/raw/<시각>/` 에 원본이 저장됩니다.

## 알려진 한계

- 작년 시점별 자료에 없는 전형(농어촌·사회배려·기회균형·실기 세부종목 등)은
  「2026 동시점」이 비고, 예측은 대학·유형 이상의 넓은 배율로 나옵니다.
  9월 10일 18시 수집(33개 대학)에서는 모집단위의 4할가량이 그렇습니다. 대부분 정원외·특기자·타 캠퍼스입니다.
- 마감 시각은 대학 페이지 공지에서 읽습니다. 공지가 없거나 작년 문구가 남아
  있으면(2026년 원광대가 그랬습니다) 다른 대학들의 마감일로 대신하고
  「대학별 기준시각」 탭 비고에 사유를 적습니다.
- 페이지가 「최종」이라 적어야 최종으로 봅니다. 공지문의 「최종 경쟁률은 …
  이후 공지」 같은 문구는 최종으로 치지 않습니다.
