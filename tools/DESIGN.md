# 수시 또래비교·추천 도구 설계서 (peer 분석)

작성: 설계 세션(Fable). 구현 세션(Opus)이 이 문서와 `tools/parse_susi.py`만 보고
데이터 내장 HTML을 완성할 수 있도록 쓴 인수인계 문서다.

## 0. 절대 원칙 — 개인정보·웹 흔적

- 입력 엑셀(나주고 파일)에는 **학생 실명·반·번호**가 들어 있다.
- 이 저장소는 public이고 GitHub Pages로 공개 중이다. 따라서:
  - **엑셀 원본, 파서 출력 JSON, 데이터가 내장된 HTML은 절대 커밋·푸시하지 않는다.**
    (루트 `.gitignore`에 차단 패턴 있음. 커밋 전 `git status`로 확인할 것)
  - 완성된 데이터 내장 HTML은 **채팅 파일 전송으로만** 사용자에게 전달한다.
    Artifact 게시, Pages 배포, 외부 업로드 금지.
  - 파서는 이름을 출력에서 제거하고 익명 ID만 남긴다(`N2026-001`, `J-00001`).
    화면에도 이름·반·번호를 표시하지 않는다 ("2024년 선배 (전과목 4.3)" 수준까지만).

## 1. 입력 자료 3종

| 자료 | 형태 | 규모 | 비고 |
|---|---|---|---|
| 전남 수시지원 결과 | xlsx, `진학결과` 시트 | **2026학년도(2025년 접수)**, 91개교, 지원 56,948행 | 학생 ID 없음(블록 추론), 실명 없음 |

> **연도 주의**: 전남 파일의 '학년도' 열과 파일명의 '2025'는 접수 연도 표기다. 나주고 2026
> 시트 학생 124명 전원의 성적 프로필(123명은 지원 대학 목록까지)이 전남 파일과 일치함을
> 확인 — 즉 같은 2026학년도 자료이고 **나주고 2026 지원건이 전남 파일에 포함**되어 있다.
> 따라서 ① 입결 조인은 2026년으로(모델 AUC 교과 .755→.807, 종합 .756→.782),
> ② 나주고 2026을 검증셋으로 쓰면 자기 자신 예측(누수)이므로 금지.
| 나주고 수시지원 결과 | xlsx, 연도별 시트 5개 | 2022~2026, 학생 582명, 지원 3,258행 | **실명 포함** |
| 대학 입결 | 이 저장소 `index.html`의 `<script id="raw-data">` JSON | 196개 대학 68,919행, 2022~2026 | 공개 자료 |

입결 JSON 컬럼: `지역, 대학, 연도, 카테고리(교과/종합/…), 전형, 학과, 계열, 모집, 경쟁률, 등급50, 등급70, 지원`

### 시트 구조의 함정 (파서가 이미 처리함 — 수정 시 참고)

1. 나주고 시트는 1~2행이 병합 헤더. 병합 전개 + **빈 셀 이어받기**(2026 시트 수능 블록은
   병합이 아니라 빈 셀) 필요 → `naju_headers()`.
2. **2025 시트는 16열부터 데이터가 헤더보다 +2열 밀려 있다** (내신 점수·등급이
   일반/환산×점수/등급 4열인데 헤더는 2열). `detect_offset()`이 최종단계 값(합격/불합격/충원합격)
   위치를 스캔해 자동 감지한다.
3. 2022 시트는 열 이름 체계가 다르고(`전형`, `후보순위`, `합격자발표`) 수능·환산등급 열이 없다.
4. 전남 파일은 학생 식별자가 없다. 같은 학생의 지원 건이 연속행으로 붙어 있고 성적 프로필이
   동일하므로 연속 블록으로 학생을 추론한다(10,406명 복원). 한계: 성적이 전부 빈 인접 학생은
   병합될 수 있음(전체의 ~1%, 지원 6건 초과 블록 ~4%는 노이즈로 간주하고 등급 기반 분석에서
   자연 제외됨 — 등급이 없으면 어차피 매칭 대상이 아님).

## 2. 파서 사용법과 출력 스키마

```bash
python3 tools/parse_susi.py <전남.xlsx> <나주고.xlsx> <출력.json> index.html
```

4번째 인자(index.html)를 주면 대학명을 입결 데이터의 정확한 표기로 치환한다(조인 키 확정).
실측 매칭률 98.2% — 미매칭 잔여는 KAIST·GIST·UNIST·DGIST·POSTECH·한국에너지공대(입결 DB에
원래 없음)와 전문대(광주보건대 등). 이들은 조인 없이 "입결 정보 없음"으로 표시하면 된다.

출력 JSON:

```
{ "jeonnam": { "students": [...], "apps": [...] },
  "naju":    { "students": [...], "apps": [...] } }

student = { id, year, grades: {전과목, 국수영사과, 국영수사, 국영수과, 국영수, 국영사, 수영과,
            (나주고만) 국어·영어·수학·사회·과학},
            sat: {국어등급, 수학등급, 영어등급, 탐구1등급, 탐구2등급, 한국사등급},
            gu: "시"|"군" (전남만), apps: [apps 인덱스] }
app = { univ(입결 표기로 정규화됨), univ_full(원표기), region, cat(교과|종합|논술|실기|수능|기타),
        adm(전형명), adm_detail(나주고만), track(인문|자연|예체능|공학|공통), major(모집단위),
        stage1, final(합격|충원합격|불합격|null), reg(등록=실제 진학 여부, bool),
        conv_grade(나주고만, 대학별 환산 내신) }
```

주의: 전남의 `final`은 원자료가 합/불 2값이라 충원합격 구분이 없다(합=충원 포함으로 추정).
나주고는 합격/충원합격이 구분된다. 5년 합산 나주고 합격 중 **충원합격이 55%** — UI에서 충원
여부를 반드시 노출할 것.

### 정규화 규칙(파서 내장)

- 대학명: `대학교→대`, `여자대학교→여대`, `교육대학교→교대`, `외국어대학교→외대`,
  "국립" 접두어는 입결 쪽 표기 따름(국립 유무 무시 매칭). 캠퍼스 분리:
  `전남대(여수)→전남대(여)`, `단국대(용인/죽전)→단국대(죽전)`, `단국대(천안)→단국대(천안)`,
  `한국외대(용인)→한국외대(글)` 등 — `univ_short()`의 BRANCH/SPECIAL 표 참고.
- 전형유형→카테고리: `학생부위주(교과)→교과`, `학생부위주(종합)→종합`, `논술위주→논술`,
  `실기/실적위주→실기`.
- 학과 조인 키: 공백·`·ㆍ()[]` 제거(`norm_major`). 접미사(학과/학부/전공)는 조인 시에는
  유지하되, "인기 학과 집계"에서만 제거해 묶는다.

### 입결 조인 전략 (3단계 폴백, 실측 조인율)

1. `(연도, 대학, 카테고리, 정규화학과)` → 2. `(연도, 대학, 정규화학과)` →
   3. `(연도, 대학, 카테고리)`의 등급50 **중앙값** (학과 미상 폴백)
- 전남(2025 고정): 학과 단위 68.8% + 대학 단위 폴백 17.3% = 86%
- 나주고(지원 연도와 입결 연도 매칭): 학과 단위 81%
- 나주고는 지원 연도의 입결과 매칭하고, **추천 표시용 입결은 최신 연도(2026 우선, 없으면 최근값)** 사용.

## 3. 통계 분석 결과 (설계 근거)

전남 2025 자료 기준. 구현 시 하드코딩하지 말고 **빌드 시 데이터에서 재계산**할 것
(아래 수치는 검증용 기준값).

### 대표등급 정의

`g = 전과목 ?? 국수영사과`. 두 값은 사실상 동일(7,025명 쌍 기준 평균차 0.00, 표준편차 0.10).
전과목 보유 67%, 국수영사과 보유 94% → 병합 시 95% 커버.

### 등급 밴드별 표본 (0.5 단위)

1.0~1.5: 159명 / … / 3.0~3.5: 733명 / 4.0~4.5: 977명 / 5.0~5.5: 1,173명 /
6.5~7.0: 684명 / 8.0~8.5: 149명. → **±0.25 창으로도 중간 등급대는 300~600명**의 또래 확보.
극단(1등급대, 8등급대)은 창 확장 필요.

### 핵심 발견: 격차(gap)-합격률 곡선

`gap = 내 등급 − 해당 학과 입결 등급50` (양수 = 내가 더 불리). 합격률(충원 포함):

| gap | 교과 | 종합 |
|---|---|---|
| −1.5 | 93% (n=162) | 36% (n=95) |
| −1.0 | 89% (n=668) | 47% (n=281) |
| −0.5 | 79% (n=2062) | 52% (n=1095) |
| 0.0 | 52% (n=5426) | 34% (n=3385) |
| +0.5 | 33% (n=4553) | 19% (n=3284) |
| +1.0 | 32% (n=2985) | 14% (n=2050) |
| +1.5 | 31% (n=2010) | 7% (n=1020) |
| +2.0 | 26% (n=2733) | 6% (n=977) |

- 교과는 gap에 대해 급경사(−0.5→+0.5 사이 79%→33%) — 등급이 거의 전부.
- 종합은 곡선이 낮고 평평 — 등급 설명력이 절반 이하. UI에 "종합은 서류·면접 영향이 큼" 고지.
- 나주고 5년 자료(연도 매칭)에서도 같은 형태 재현(전반 +15%p 수준, 표본 소·연도 효과).
- 논술 합격률 1~5%, 실기 16~25%: 등급 기반 예측 불가 → 추천 대상에서 제외하고 사례만 표시.

### 그 밖의 설계에 쓰인 사실

- 학생당 지원: 6건이 최빈(72%). 수시 6회 제한과 일치 → 블록 추론 타당성 방증.
- 등급대별 합격률 총계는 밴드와 무관하게 교과 ~45%, 종합 ~25%로 일정
  (학생들이 이미 자기 수준에 맞춰 지원하는 자기선택 효과) → **절대 등급이 아니라 gap이 예측변수**.
- 등록(실제 진학) 기반 선호 대학이 등급대별로 뚜렷한 계층: 1~2등급 전남대·수도권 상위,
  3등급 전남대·전북대, 4~5등급 조선대·순천대·목포대·원광대, 6~7등급 동신대·광주대·호남대.
  인기 학과도 계층적(2자연 간호·기계, 4~6자연 간호·물리치료·보건, 2인문 초등교육·경영 등).
  → 추천 후보는 이 "또래 지원 분포"에서 생성하는 것이 현실적 선호를 반영한다.

### (개정) 확률 모델 v2 — 힌지 로지스틱 + 경쟁률

구현 세션에서 홀드아웃 검증으로 모델을 업그레이드했다. §4의 "gap 곡선 보간"은
**힌지 로지스틱 회귀**로 대체됨 (`build_peer_data.py`가 빌드 시 재적합해 계수를 내장):

- `P(합격) = σ(w0 + w1·min(gap,0) + w2·max(gap,0) + w3·log(경쟁률))`, 카테고리별 별도 적합.
- 학생 단위 80/20 홀드아웃(전남 2025): AUC 교과 .746 / 종합 .750
  (버킷보간 .674/.687, 로지스틱 gap만 .677/.684 → **경쟁률이 gap과 독립적인 강한 예측변수**).
- 베이즈 혼합 강도 m은 그리드 {2,4,8,12,20,40}에서 홀드아웃 Brier 최소값 채택(실측 m=2).
- 외부검증: 전남 학습 → 나주고 5년 적용 AUC .83(교과)/.75(종합). 나주고 관측 합격률이
  예측보다 +13%p 높음(과거 연도 완화) → UI에 "보수적 예측" 고지.
- 추가 구현: Wilson 95% CI(또래 합격률), 대학 평균 폴백 조인 표시 배지,
  조합등급(g7) 선택 반영, 나주고 최저학력기준 원문 추출(`minreq`)과
  "N개 영역 합/각 M이내" 패턴 자동 판정(참고용 배지).

### (개정) 또래 창 타당성 백테스트와 커널 로컬 추정

"나주고 학생이 이 도구를 썼다면"을 전제로 창 크기를 검증했다(누수 없는 나주고
2025·2022~24 코호트, 전남 데이터로 후보·확률 산출 후 실제 합불과 대조):

- **확률 정확도**: 좁을수록 좋음(±0.15 > ±0.25 > ±0.5). 최적은 고정 창이 아니라
  **삼각커널 h=0.3**(거리에 따라 가중 감소) — 인접 코호트 Brier .1645, AUC .838.
- **후보 커버리지**(실제 지원한 곳이 추천 후보에 잡히는 비율): 넓을수록 좋음.
  ±0.25 적응형에서 73%, ±0.5로 넓혀도 +9%p뿐이라 ±0.25 적응형 유지가 균형점.
- **결론(구현됨)**: 후보 생성·표시는 기존 적응형 하드 창(±0.25, 또래<150명이면 확장)
  유지, **확률의 로컬 관측만 삼각커널 h=0.3**으로 분리. 혼합 강도 m=2 재확인.

## 4. 추천 알고리즘 (구현 사양)

입력: 대표등급 `g`(숫자 입력, 또는 조합등급 직접 선택), 계열(인문/자연/예체능),
선택 필터(지역 멀티선택, 대학 검색어, 학과 키워드, 전형 카테고리), (선택) 수능 등급 4개.

1. **또래 집합**: 전남 학생 `|g′−g| ≤ w`, w=0.25에서 시작해 또래 <150명이면 0.05씩 확장
   (상한 0.75). 나주고 또래는 `|g′−g| ≤ 0.5` 고정(5개년 합산, 표본 소).
2. **후보 생성**: 또래의 지원 건을 (대학, 학과, 카테고리)로 집계(필터 적용, 논술·실기 제외).
   지원 2건 이상만 후보로.
3. **확률 추정**: 카테고리별 gap-합격률 곡선을 전체 전남 데이터에서 0.25 구간으로 산출(선형 보간,
   구간 n<30이면 이웃 구간과 병합). 후보의 gap = g − 등급50(최신 연도, 3단계 조인).
   또래-로컬 관측(해당 대학·학과 지원 n, 합격 k)이 있으면 베이지안 혼합:
   `P = (k + m·P_curve) / (n + m)`, m=10.
   입결 조인 실패 시 P 미표시("입결 정보 없음"), 또래 관측만 표시.
4. **분류**: 안정 P≥65% / 적정 40~65% / 소신 15~40% / 상향 <15%.
5. **정렬·노출**: 그룹별로 또래 지원수(인기도) 순. 기본 안정 3 · 적정 5 · 소신 3, 더보기 지원.
6. **근거 카드**(추천 1건당):
   - 입결: 최신 등급50/70, 경쟁률, 모집인원, 최근 3년 등급50 추이(미니 스파크라인)
   - 전남 또래: "등급 X.X±w 또래 n명 지원 → k명 합격 (합격률 %)"
   - 나주고 사례: 연도·전과목 등급·전형·결과(합격/충원/불합격)·등록 여부 목록 (익명, 최대 5건)
   - 종합 전형이면 "서류 영향 큼" 배지, 최저학력기준 있는 전형은 사용자가 수능 등급을
     입력한 경우 나주고 자료의 `최저학력기준` 텍스트 참고 표시(v1은 텍스트 노출까지만)

## 5. HTML 구현 사양 (peer.html → 데이터 내장본은 별도 파일명)

- **저장소에는 데이터 없는 뼈대 `peer.html`만** 커밋 가능(선택). 데이터 내장 완성본은
  `peer-local.html` 같은 별도 이름으로 만들어 **채팅 전송만** 하고 `.gitignore`로 차단.
- 단일 파일, 오프라인 동작 목표. 차트는 index.html처럼 Chart.js CDN을 써도 되지만
  CDN 실패 시 표 폴백 필수(교무실 인트라넷 고려).
- 데이터 내장: 원시 JSON 16.9MB → **컬럼형 배열**(index.html의 raw-data 방식)로 축소해
  내장(추정 4~6MB). 필요 시 gzip+base64 + `DecompressionStream('gzip')`(약 1.6MB)도 가능하나
  구형 브라우저 폴백이 없으므로 컬럼형을 기본으로 권장. `univ_full`은 미매칭 건만 유지.
- 입결 데이터는 index.html에서 추출해 함께 내장(공개 자료라 제약 없음).
- 화면 구성:
  1. 상단 입력부: 등급 입력(숫자+슬라이더), 계열, 전형, 지역/대학/학과 필터 (index.html의
     필터 UI 관례 재사용)
  2. **추천 탭**: 안정/적정/소신 3열 카드(§4의 근거 카드)
  3. **또래 탭**: 또래 지원 분포 — 선호 대학 top, 인기 학과 top(접미사 정리해 묶기),
    합불 산점도(x=입결 등급50, y=내 등급, 색=결과; index.html 산점도 관례 재사용)
  4. **나주고 선배 탭**: 등급 창 내 선배들의 연도별 지원·결과 테이블(익명), 충원합격 비율 강조
  5. 모바일 대응·다크모드는 index.html 관례 따름
- 개인정보 표시 규칙 재확인: 이름·반·번호 미표시, 익명 ID도 화면에는 숨기고
  "2024년 선배(전과목 4.3)" 형식만.

## 6. 구현 세션(Opus) 작업 순서

1. 사용자에게 엑셀 2개 재업로드 요청 (세션 컨테이너는 휘발성).
2. `python3 tools/parse_susi.py 전남.xlsx 나주고.xlsx /tmp/.../parsed.json index.html` 실행,
   콘솔 출력이 이 문서의 기준값(학생 10,406/582, 매칭 98.2%)과 일치하는지 확인.
3. gap 곡선·밴드 표본을 재계산해 §3 기준값과 대조(±2%p 이내면 정상).
4. 컬럼형 데이터 변환 → 완성본 HTML 빌드 → 로컬에서 열어 스모크 테스트
   (등급 3.5 자연 입력 시 간호·공학 계열 후보가 나오는지 등).
5. **커밋 전 `git status`로 데이터 파일이 스테이징되지 않았는지 확인** 후, 코드 변경분만
   커밋. 완성본 HTML은 채팅으로 전송.
