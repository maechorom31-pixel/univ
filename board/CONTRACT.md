# 수시 상담 보드 — 파트 사이의 계약

이 문서가 정본이다. 각 파트(P0~P8)는 서로의 코드를 읽지 않고 **이 문서만 보고** 만든다.
여기 적힌 이름·모양을 바꿔야 한다면 코드보다 이 문서를 먼저 고친다.

저장소 전체의 구조와 자료 흐름은 [`../ARCHITECTURE.md`](../ARCHITECTURE.md) 에 있다.

## 1. 개인정보 경계

두 층으로 나눈다. 이 경계를 넘는 코드를 쓰면 안 된다.

| | 어디에 | 무엇이 | 누가 읽나 |
|---|---|---|---|
| **공개** | GitHub Pages `data/*.json` · `../College/data/departments.json` | 일반대 입결 · 모집요강 · 전문대 | 브라우저가 직접 `fetch` |
| **개인** | 교사 구글시트 (Apps Script) | 학생 이름 · 성적 · 지원 · 메모 · 결과 | 배포 주소를 아는 사람 |

**잠금은 배포 주소다.** 선생님들이 학교 컴퓨터·집·휴대폰을 오가며 쓰기 때문에
구글 계정으로 고정하면 정작 써야 할 사람이 막히는 일이 더 잦다. 그래서 기본은 열어 두고,
**주소를 공유하지 않는 것**을 잠금으로 삼는다. 계정을 지정해 잠그려면 시트의 `설정` 탭
A열에 적으면 그 순간부터 그 명단만 들어온다.

담임이 볼 반은 서버가 아니라 **화면에서** 정한다. 학교 컴퓨터를 여럿이 나눠 쓰므로
컴퓨터마다 기본 반을 기억해 두고(`localStorage`), 다른 반이나 학년 전체로는 화면에서 바꾼다.
서버는 언제나 학년 전체를 보낸다.

- 학생 이름·성적은 **저장소에 절대 커밋하지 않는다.** 엑셀 원본도 마찬가지다
  (루트 `.gitignore`가 `*.xlsx`를 막는다).
- 공개 쪽으로 학생 식별자를 보내는 요청을 만들지 않는다.
- 결합은 브라우저 안에서만 일어난다.

## 2. 값 객체

### 2.1 `Student` — 학생

즐겨찾기 export 한 학생의 여러 행에서 **중복 없이 한 번만** 뽑는다.

```js
{
  hak:      "3217",        // 학번 4자리 = 3학년 2반 17번. 모든 곳에서 이걸 키로 쓴다
  grade:    3,
  cls:      "2",           // 반. 문자열 (지원자격상 "특수" 같은 값이 올 수 있음)
  no:       "17",
  name:     "최예은",
  naesin:   { "전교과": 3.20, "국영수": 3.28, ... },  // 조합명 → 등급. 있는 것만
  suneung:  {                                        // 없으면 {}
    "한국사": { grade: 4 },
    "국어":   { subject: "화법과 작문", std: 88, pct: 31, grade: 6 },
    "수학":   { subject: "확률과 통계", std: 80, pct: 25, grade: 6 },
    "영어":   { grade: 6 },
    "탐구1":  { subject: "생활과 윤리", std: 59, pct: 78, grade: 3 },
    "탐구2":  { subject: "윤리와 사상", std: 50, pct: 53, grade: 5 },
    "제2외국어": { subject: "", grade: null }
  },
  apps:     ["a1b2c3d4", ...]   // Application.id 목록. 입력 순서 유지
}
```

`naesin` 키는 export 헤더를 그대로 쓴다 — `전교과` `국영수` `국영수사` `국영사`
`국영수과` `수영과` `국영수사/과` 등. 조합별 가중치 열(`2/4/4` 같은 하위 헤더)은
`전교과(2/4/4)` 처럼 괄호를 붙여 구분한다.

### 2.2 `Application` — 지원 한 건

export 한 행 = 한 건.

```js
{
  id:        "a1b2c3d4",   // 안정키. §3 참고
  hak:       "3217",
  univType:  "일반대",      // 일반대 | 전문대 | 특수대
  region:    "부산",
  univ:      "부산외국어대학교(부산)",   // 원문 그대로. 캠퍼스 포함
  period:    "수시",        // 수시 | 수시1차 | 수시2차
  typeCat:   "학생부위주(교과)",        // 전형유형
  typeName:  "학생부교과우수자",         // 전형명(대)
  typeSub:   "학생부교과(일반고교과)",   // 세부유형
  track:     "공통",        // 계열
  dept:      "통합모집(자유전공)",       // 모집단위. 원문 그대로
  quotaText: "(29)",        // 모집인원 원문. 괄호는 정원 외를 뜻한다
  quota:     29,            // 숫자만. 못 뽑으면 null
  selectType:"일괄합산",     // 일괄합산 | 단계별전형 | 혼합활용
  minReqText:"* 수능최저기준: …",       // 원문. 없으면 ""
  myScore:   { score: 966.0, grade: 4.40 },   // 내점수(환산) / 내등급(환산). 없으면 null
  dates: {                  // §4. 없는 종목은 키 자체가 없다
    면접:   { from:"2025-11-29", to:"2025-11-30" },
    최종발표:{ from:"2025-12-05", to:"2025-12-05" }
  },
  result: {                 // 발표 전에는 전부 null
    stage1: null, final: null, reason: null, waitNo: null, enrolled: null
  },
  unknown: { "새 컬럼명": "값" }   // 헤더 사전에 없던 컬럼. 비었으면 {}
}
```

`quota` 규칙 — `"586"` → 586 · `"(29)"` → 29 · `"7(<10)"` → 7 · `""` → null.

### 2.3 `Link` — 입결·모집요강 연결 (P0 `match.js`가 만든다)

```js
{
  key:      "부산외대|자유전공",   // 정규화 키
  kind:     "univ" | "college",   // 어느 자료를 봤는가
  ipgyeol:  [ IpRow, ... ],       // 일반대: data/ipgyeol.json (연도 오름차순)
  college:  [ ColRow, ... ],      // 전문대: ../College/data/departments.json
  mojip:    [ MojipRow, ... ],    // data/mojip2027.json 에서 고른 행들
  related:  [ "경영", "경제" ],    // 통합·자유전공일 때 함께 볼 학과 키
  confidence: "exact" | "loose" | "none",
  why:      "대학·학과 정확히 일치"  // 사람이 읽을 사유. 화면에 그대로 쓴다
}
```

`summarize(link, app)` 가 여기서 화면용 `Summary` 를 만든다. 컷·경쟁률·모집인원은
**`mine` 에서만** 온다 — `rows` 전체가 아니다.

```js
{
  rows:    [ IpRow, ... ],   // 이 학과의 모든 전형·모든 해 (연도별 추이가 쓴다)
  mine:    [ IpRow, ... ],   // 그중 지원한 전형의 줄만 (연도 오름차순)
  type:    "교과(일반)",       // 입결 쪽 전형 이름 — 즐겨찾기와 다를 수 있다
  typeFit: "exact" | "near" | "cat" | "only" | "none",
  among:   [ "교과(추천)", "교과(학교장추천)" ],  // none 일 때만. 후보 이름들
  isNew:   true,             // 올해 신설 (모집요강의 작년 모집인원·경쟁률이 둘 다 빔)
  nearby:  { sole, groups }, // 신설일 때 곁들이는 관련 전형. mine 은 비어 있다
  alias:   { toUniv, toDept, note },  // 선생님이 점검 화면에서 손으로 이어 둔 것
  stale:   { year, hi, deptHi, heirs },  // 고른 전형이 학과 자료보다 일찍 끊겼으면
  year,                      // 아래 숫자가 어느 해 것인지. 「작년」이 아닐 수 있다
  cut, cut50, rate, quota, ...                 // mine 에서 컷이 있는 가장 최근 해
}
```

**전문대는 자료가 다르다.** 일반대가 `등급70 / 등급50 / 경쟁률`을 준다면,
전문대는 `평균등급 / 최저등급 / 경쟁률`을 3개년(앞이 최신)으로 주고
취업률·충원율·연계편입이 함께 온다. 카드도 그에 맞춰 다른 값을 보여 준다.
`특수대`(사관학교 등)는 어느 자료에도 없어 `none` 으로 두고 사유를 밝힌다.

즐겨찾기가 `간호학과(4년제)` 처럼 수업연한을 학과명에 넣는데 College 자료는
그것을 `level` 이라는 별도 값으로 갖고 있다. 이름으로 못 붙으면 구분자를 떼고
다시 찾은 뒤 수업연한으로 가린다.

`confidence: "none"` 이면 카드에 **「연결 안 됨」 배지**를 띄우고 미연결 큐에 넣는다.
값을 지어내지 않는다.

### 2.4 `BoardState` — 6칸 배치 (시트에 저장)

```js
{
  id:    "a1b2c3d4",    // Application.id
  hak:   "3217",
  slot:  "rank" | "pool" | "archive" | "tray",
  rank:  1,             // slot이 "rank"일 때 1~6. 아니면 null
  by:    "kim@…",       // 마지막으로 바꾼 교사
  at:    "2026-09-02T10:11:00+09:00"
}
```

- `rank` 는 **일반대만** 쓴다. 전문대·특수대는 `tray` 이고 `rank` 는 항상 `null`.
- 같은 학생 안에서 `rank` 는 겹칠 수 없다. 겹치면 `at` 이 늦은 쪽이 이긴다.

## 3. 안정키 — `Application.id`

원본 엑셀은 계속 바뀐다. 그 위에 쌓은 메모·순위·결과가 살아남아야 한다.

```
id = sha1( hak + "\u0001" + univ + "\u0001" + typeSub + "\u0001" + dept ).slice(0, 16)
```

- `typeName` 이 아니라 **`typeSub`(세부유형)** 을 쓴다. 같은 대학·학과에 여러 전형을
  지원할 때 이것이 갈라 주고, 해마다 표기가 덜 흔들린다.
- 각 조각은 앞뒤 공백을 지우고 연속 공백을 하나로 줄인 뒤 넣는다.
- 대학명은 **원문 그대로** 넣는다(정규화하지 않는다). 정규화 규칙이 바뀌어도
  기존 메모가 떨어지지 않게 하기 위해서다.

## 4. 날짜

export와 모집요강 모두 **기간 표기가 흔하다**(면접일정의 41%).
그래서 날짜는 세 상태를 갖는다.

```js
{ from: "2025-11-29", to: "2025-11-30", fixed: false }   // 기간
{ from: "2025-11-29", to: "2025-11-29", fixed: true  }   // 확정 (하루)
// 값 자체가 없으면 키가 없다 = 미정
```

- `from === to` 이면 `fixed: true` 로 둔다.
- 학생이 배정받은 날을 넣으면 `fixed: true` 가 되고 `from = to = 그 날`.
- 겹침 판정: 둘 다 `fixed` 면서 같은 날 → **충돌**. 한쪽이라도 기간이면 → **겹칠 수 있음**.

파서가 받아들여야 하는 원문 형태:
`2025-11-29 ~ 2025-11-30` · `2025-11-29` · `11.25(수)~11.27(금)` · `12월 18일(금)까지` ·
`2025.12.12.(금) 14:00`. 못 읽으면 키를 만들지 않고 `unknown` 에 원문을 남긴다.

## 5. 모듈 인터페이스

### 5.1 `board/api.js` — 백엔드 통신 (P0)

```js
api.configure(url, { persist })   // Apps Script 배포 URL. persist:false 면 이 화면에서만
api.configured() · api.url()
await api.call(action, params)    // JSONP. 실패 시 2회까지 재시도
await api.students()              // → { students, apps, state, notes, results, dates, aliases }
await api.setState(BoardState) · api.addNote(...) · api.setResult(...) · api.setDate(...)
```

**한 번에 다 받는다.** `students` 하나가 학생·지원·배치·메모·결과·일정·별칭을 함께
돌려준다. 칸마다 따로 부르면 JSONP 왕복이 늘고, 무엇보다 **화면이 반쯤 채워진 상태**가
생긴다. 배치는 왔는데 결과는 안 온 순간에 담임이 판단을 내리면 안 된다.

`persist: false` 는 학생 화면이 쓴다. 링크의 `?api=` 를 브라우저에 남기면, 선생님이
학생 링크 하나를 자기 브라우저에서 열어 보는 것만으로 **교사 보드의 서버 주소가
바뀐다** — 둘이 같은 열쇠를 쓰기 때문이다. 링크는 남이 만들어 보낼 수도 있다.

JSONP 는 GET 이라 주소 길이에 한계가 있다. 한글은 URL 인코딩으로 글자당 아홉 자리가
되어서, 긴 메모는 800자쯤부터 위험하다. **보내기 전에 막고 왜 못 보내는지 말한다** —
잘려서 절반만 저장되면 아무 데도 「잘렸다」고 안 적힌다.

모든 응답은 `{ ok: true, ... }` 또는 `{ ok: false, error: "사람이 읽을 문장" }`.
`ok: false` 를 조용히 삼키지 않는다 — 화면에 그대로 띄운다.

### 5.2 `board/store.js` — 자료 적재 (P0)

```js
await store.ready()          // 공개 JSON 3종을 받아 색인까지 끝낸 뒤 resolve
store.ipgyeol                // { columns, rows }  data/ipgyeol.json
store.mojip                  // { columns, rows }  data/mojip2027.json  (문자열 사전 방식)
store.students               // Map<hak, Student>
store.apps                   // Map<id, Application>
store.link(app)              // → Link  (match.js 결과를 캐시)
store.summary(app)           // → Summary (위 §2.3)
store.resultOf(app) · store.dateOf(app, kind)
store.pendingResults(cls) · store.pendingDates(cls)   // 담임의 「오늘 할 일」
store.approveResult(app) · store.approveDate(app, kind)
store.unmatched(cls)         // 못 붙인 학과 묶음 (「없음으로 표시」한 것은 skipped:true)
```

보드가 받는 공개 자료는 **넷**이다 — 입결 · 모집요강 · 전문대(College 저장소) ·
전형일정. `xref.json` 은 여기 안 들어온다. 그건 `planner.html` 이 내장해 쓰는 것이고,
보드는 `match.js` 가 그때그때 이름을 맞춘다.

`store` 는 상태를 들고 있을 뿐 화면을 그리지 않는다. 화면 갱신은 이벤트로 알린다.

```js
store.on("change", (what) => { … })   // what: "state" | "notes" | "results" | "data"
```

### 5.3 `board/student.js` · `board/links.js` — 학생 화면과 링크 (P5)

```js
// student.js  — 학생 링크(student.html?s=토큰&api=…)로 연다
start(token, demoData?)     // 자기 지원만 그린다

// links.js — 교사 화면의 「학생 링크」 칸
start()                     // 반 단위로 토큰을 만들고 표·CSV·문자 문구로 뽑는다
```

- 학생 경로는 **토큰으로만** 연다. 서버가 토큰 → 학번을 풀고, 그 학번의 것만 내준다.
  쓰기도 `ownsApp_()` 로 본인 지원인지 확인한 뒤에만 받는다.
- 학생이 넣은 값은 `status: "pending"`(확인 대기)으로 들어간다.
  담임이 「맞습니다」를 눌러야 `confirmed` 가 된다. 잘못 적은 날짜로 여섯 칸 판단이
  흔들리면 안 되기 때문이다.
  **확인 전에는 겹침을 「겹칠 수 있음」까지만 말한다** (`clashes` 가 `status` 를 본다).
  그러지 않으면 pending 이 확정과 똑같이 「겹침」 경고를 만들어, 이 칸을 둔 까닭이
  없어진다. 확인하는 자리는 두 곳 — 보드 첫 화면의 「학생이 넣은 날짜」와 일정판의
  그 줄. 결과 쪽 「맞습니다」와 같은 흐름이다.
- **모의면접은 학교가 정한다.** 자동으로 D-3을 잡아 두지 않는다 — 다른 학생과 겹치고
  교실 사정도 있다. 선생님이 넣은 날짜가 학생 화면에도 그대로 간다.
  여러 번 잡히면 「1차 · 2차」로 함께 적는다.
- **차례는 지금이 몇 월인가로 정한다.** 9월 원서철에 학생이 여는 이유는 여섯 칸을
  정하는 것이지 날짜가 아니다.

      곧 있습니다(7일 안일 때만) · 지원 6칸 · 숫자 읽는 법
      · 그 밖의 지원 · 다가오는 일정 · 겹치는 날

  「곧 있습니다」는 **7일 안에 아무것도 없으면 아예 안 그린다.** 9월에는 저절로 안
  보이고 11월 면접철에는 저절로 맨 위에 온다. 켜고 끄는 단추를 두지 않는 까닭이다.

### 5.4 `board/schedule.js` — 일정판 (P4)

```js
eventsOf(apps)     // 지원 목록 → [{hak, name, app, kind, from, to, fixed}] 날짜순
clashes(events)    // → [{a, b, sure}]  sure=true 면 확정 겹침, false 면 「겹칠 수 있음」
suggestMock(from)  // 면접 사흘 전 — 제안일 뿐이고 실제 날짜는 선생님이 넣는다
                   // 모의면접은 여러 번 — 칸 이름이 모의면접1 … 모의면접5
start()            // #schedule 칸에 그린다
```

- **가야 하는 것**(면접·실기·논술·적성)만 겹침을 따진다. 발표는 겹쳐도 상관없다.
- 확정 겹침을 목록 위로 올린다. 「겹칠 수 있음」이 앞을 막으면 급한 걸 놓친다.
- 학생을 고르면 달력, 고르지 않으면 반 전체를 날짜순으로. 담임에게는
  「그날 누가 어디로 가는지」가 자주 보는 화면이다.
  **그래서 학생을 고른 뒤에도 반 전체로 돌아갈 단추를 둔다.** 예전에는 반을 바꿀 때만
  선택이 풀려서, 반이 하나뿐이면 반 전체 일정에 영영 못 갔다.
- **확정 겹침과 「겹칠 수 있음」을 따로 센다.** 뭉쳐서 「겹치는 날 5건」이라 적으면
  하나를 버려야 하는 진짜 겹침 한 건이 기간 때문에 생긴 잠재 넷에 묻힌다.

**면접 칸은 대학으로 묶는다** (`interviewPanel` → `univBlock`).

모의면접은 한 전형에 **여러 번** 잡을 수 있다(`모의면접1` … `모의면접5`).
그래서 이 이름을 **글자 그대로 견주면 안 된다.** 달력이 `kind === '모의면접'` 으로 재는
바람에 한 번도 안 맞아, 모의면접이 대학에 실제로 가는 날과 똑같이 칠해졌다 —
범례에 따로 두고도 구별이 안 됐다. 학생이 이걸 보고 학교에 있어야 할 날을 대학 가는
날로 읽으면 큰일이다. `isMock()` 으로 본다(예전 방식 `모의면접` 하나도 함께 걸린다).
면접 전형이 넷인 학생이 세 번씩 모의면접을 하면 열여섯 줄이 섞여 나온다. 그러면
「숭실대 준비가 어디까지 됐나」를 눈으로 못 센다. 그래서 한 대학이 한 덩이고,
그 안에 대학이 정한 날 · 잡아 둔 모의면접(차수와 지우기) · 다음 차수 넣기가 들어간다.

**전문대·특수대도 면접 전형이면 덩이를 받는다.** 입결도 전형일정표도 없어 날짜가
비어 있을 뿐, 학생은 똑같이 그날 거기 가야 한다. 자료가 없는 것과 일정이 없는 것은
다른 말이라, 빈 덩이에 날짜를 손으로 넣는 줄(`missingRow`)을 둔다.

모집요강(`data/mojip2027.json`)의 `모집단위`에 `[유형1]`·`[유형2]` 꼬리표가 붙으면
**세부모집단위는 잘게 나눈 이름이 아니라 묶이기 전 학과 목록**이다.

    [유형2] 인문사회계열   ←  모집단위
    국어국문학과, 철학과, 국사학과, …   ←  세부모집단위 = 묶이기 전 학과들

- 그래서 자유전공 행은 **모집단위 이름으로만** 색인한다. 학과 목록으로 걸면
  그 학과를 따로 지원한 학생에게 엉뚱한 전형이 붙고, 200자짜리 키가 생긴다.
- 꼬리표가 없어도 세부모집단위가 셋 이상으로 쪼개지고 대부분이 학과 이름꼴이면
  같은 것으로 본다(광역모집 단과대). 163곳이 여기 해당한다.
- 유형2 모집단위 136곳 중 **81곳**에서 묶이기 전 선을 그릴 수 있다.
  (제 입결도 있는 곳 40 · 참고선만 있는 곳 41)
- **지원한 전형과 같은 카테고리만** 모은다. 교과로 넣는 학생에게 종합 컷을
  보여 주면 없느니만 못하다. 그 카테고리가 없으면 빈손으로 돌아간다.
- 평균 하나로 줄이지 않는다. **범위와 가운데값, 그리고 학과별 값을 다** 준다.
  묶고 나면 경쟁률도 컷도 달라지므로 한 숫자로 말할 수 있는 자료가 아니다.
- 못 찾은 학과를 감추지 않는다(`missing`).

`pickMojip()` — 한 학과에 전형이 여럿이면 모집요강 행도 여럿이다. **지원한 전형과
같은 줄을 골라야 한다.** 첫 줄을 그냥 쓰면 종합으로 넣은 학생에게 논술의 작년
모집인원이 붙어 「30명 (작년 3명)」 같은 엉뚱한 증감이 뜬다.

### 5.6 `board/card.js` — 카드 상세 (P3)

```js
realRate(nominal, quota, filled)   // → {value, why}  못 구하면 value=null, why 에 사유
detailPanel(app, student, onClose) // → <section class="panel detail" role="dialog">
```

보내주신 상담 카드 시트의 항목이 그대로 명세다. 구역은 이 차례로 둔다.

    전형 · 인원과 경쟁률 · 성적 · 일정 · 전형일정표 원문 · 수능최저 · 지원자격
    · 전문대 정보 · 묶이기 전 학과 · 연도별 추이 · 이 컷을 얼마나 믿을 수 있나
    · 결과 · 상담 메모 · 알아보지 못한 칸

- **줄마다 출처를 적는다.** 즐겨찾기 / 모집요강 / 입결 / 전문대 자료.
  숫자만 놓으면 어디까지 믿을 값인지 알 수 없다.
- **값이 없는 줄은 지운다.** 단, 「등록 마감」·「미등록 충원 발표」는 값이 없어도
  「모집요강 확인」이라 적고 남긴다. 빠뜨리는 쪽이 더 위험한 항목이라서다.
- **실질경쟁률** = 명목 × 모집 ÷ (모집 + 추합). 모집+추합이 지원자보다 많으면
  추합이 누적 예비번호로 적힌 것이므로 계산하지 않고 사유를 적는다. planner.html 과 같은 식.
- **「작년」이라는 이름표는 정말 작년일 때만 단다.** 머리 숫자는 「컷이 있는 가장
  최근 줄」에서 통째로 온다. 그 줄이 학과 자료의 마지막 해보다 이르면(입결이 붙는
  카드의 7.3%) 이름표에 연도를 박는다 — 「2023년 70% 컷」. 모집요강에서 온 줄
  (작년 모집인원·실질경쟁률·추가합격)은 정말 2026년 값이라 「작년」 그대로 둔다.
- **전형이 끊겼으면 머리에서 말한다**(`Summary.stale`). 「…은 입결에 2023년까지만
  있습니다」 + 뒤를 잇는 전형과 그 컷. 잇지는 않는다 — 쪼개진 갈래 가운데 어느
  쪽인지 이름으로는 못 가린다. 뒤를 잇는 전형을 찾았으면 「70%컷 칸이 비어 있다」는
  알림은 접는다. 더 찾을 데가 없는 것처럼 읽히는데, 실제로는 뒤를 잇는 쪽에 컷이 있다.
- **미달은 말로 적는다.** 지원한 전형의 어느 해든 경쟁률이 1 미만이면
  「인원과 경쟁률」 아래에 한 줄 붙인다 — 가장 최근 해가 미달이면 「작년 경쟁률이 1을
  밑돕니다(미달)」, 아니면 미달이었던 해를 적는다. 「0.54:1」은 훑으면 그냥 낮은
  숫자로 읽힌다. 컷도 지원자 몇 명에 좌우된 값이라는 것을 함께 적는다.
  이 값들이 진짜 미달인지는 확인했다 — `ARCHITECTURE.md` 「경쟁률이 1 미만인 줄」.
  대학·학과·전형 묶음의 1.5% 라 드물다.
- **연도별 추이는 표로 둔다.** 상담에서 읽는 것은 그래프가 아니라 정확한 숫자다.
  **전형으로 먼저 묶고 그 안에서 연도 내림차순**, 묶음 사이에 굵은 선을 둔다.
  연도순으로만 늘어놓으면 교과 3.58 · 종합 5.20 · 교과 3.62 처럼 잣대가 번갈아 나와
  흐름이 안 읽힌다. 지원한 전형을 맨 위에 두고 「내가 넣은 전형」이라 적는다.
  이름이 해마다 달랐으면 **가장 최근 해의 표기**를 쓰고 「예전 이름 …」을 함께 적는다
  (`typeGroups`). 감추면 왜 한 묶음이 되었는지 알 수 없다.
  묶음은 카드 머리의 숫자를 고른 것과 **같은 함수**가 만든다. 화면에서 따로 묶으면
  표와 머리가 어긋나고, 어긋나도 아무 데도 「어긋났다」고 안 적힌다.
- 상세는 보드 본문 밖(`#detail`)에 그린다. 본문은 순위를 옮길 때마다 다시 그려지는데,
  상세까지 지워지면 메모를 적다 말고 창이 닫힌다. 다시 그릴 때 적던 메모와
  스크롤 위치는 그대로 둔다.
- 여는 길 둘 — 카드를 누르거나 「자세히」 단추. 선택 상자·단추 안에서 시작된 누름과
  끌어다 놓기 중의 누름은 흘려보낸다. 닫는 길 셋 — 닫기 단추·Esc·덮개 바깥.
- 상세를 열어 둔 채 인쇄하면 그 전형 한 장만 나온다(`body[data-detail]`).

```js
normType(name)                    // "학생부교과(일반전형)" → "교과일반"  (전형 이름 정규화)
typeGroups(rows)                  // 한 학과의 입결 행 → Map<key, {rows, keys, name, aliases, cat, lo, hi}>
pickIpgyeol(rows, app)            // → { rows, fit, type, among? }  지원한 전형의 줄만
```

`typeGroups` 는 두 가지를 한다 — `normType` 으로 묶고, 그 다음 **해가 바뀌며 이름이
바뀐 것끼리 잇는다**(고려대 `교과(추천)` 2022~25 → `교과(학교장추천)` 2026).
잇는 조건 넷: 카테고리가 같고 · 해가 안 겹치고 이어지고 · 1:1 이고 · 이름이 0.5 이상
닮았다. 1:1 조건이 없으면 강원대 `미래인재` → `미래인재1`·`미래인재2` 처럼 **쪼개진**
것을 이름이 바뀐 것으로 읽는다.

**묶는 일은 여기 한 곳에서만 한다.** `pickIpgyeol` 과 카드의 연도별 추이 표가 같은
함수를 본다. 화면에서 따로 묶으면 표와 머리가 어긋난다.

`normType` 은 괄호·공백·가운뎃점에 더해 **붙임표와 `+ _ ' ⋅` 도 턴다.** 안 털면
즐겨찾기의 `학생부종합(잠재능력우수자면접전형)` 이 입결의 `종합(잠재능력-면접)` 과
안 붙고, `near` 가 대신 2024년에 쪼개지기 **전**의 `종합(잠재능력)`(~2023)을 집는다.
털어도 같은 해 안에서 서로 다른 전형이 한 이름이 되는 일은 새로 안 생긴다
(자세한 것은 `ARCHITECTURE.md` 「붙임표도 턴다」).

```js
staleOf(rows, mineRows, latest)   // → {year, hi, deptHi, heirs:[{name, hi, year, g70, rate}]} | null
```

고른 전형이 그 학과 자료보다 **일찍 끊겼는지** 본다(`Summary.stale`). 끊겼으면
뒤를 잇는 전형까지 찾아 준다 — 같은 카테고리이고, 정규화한 이름이 고른 전형 이름을
앞에 두고 더 붙인 것이며, 더 나중 해까지 있는 것. **찾아만 주고 잇지 않는다.**
`종합(미래인재면접)` 이 `미래인재1` 인지 `2` 인지 이름으로는 못 가린다.

`normDept` 는 **`scripts/build_xref.py` 의 `norm_dept` 와 같은 규칙**이다.
한쪽을 고치면 다른 쪽도 고쳐야 하고, `board/match.test.mjs` 가 그것을 지킨다.

**학과까지만 맞추면 안 된다.** 입결은 (대학·학과)로만 묶여 있어 한 학과에 전형이
여럿 들어 있다. 학과키의 73.0% 가 가장 최근 해에만도 전형이 둘 이상이고, 그중 23.6%
는 전형끼리 70%컷이 1등급 넘게 벌어진다. `pickIpgyeol` 이 지원한 전형의 줄만 골라
`Summary.mine` 에 담는다. 고르는 차례는 `exact → near → cat → only`,
어느 것도 아니면 **`none` 으로 비운다** — 옆 전형의 숫자를 앉히지 않는다.
자세한 것은 `ARCHITECTURE.md` §5.

대학명은 표기가 셋이라 한 번 더 손이 간다.

| | 표기 | 예 |
|---|---|---|
| 즐겨찾기 | 정식 명칭 + 캠퍼스 | `한국외국어대학교(용인) - 글로벌캠퍼스` |
| 입결 | 축약형 + 캠퍼스 약자 | `한국외대(글)` |
| 모집요강 | 축약형 | `한국외대` |

`univStem` 이 `외국어대학교→외대` 같은 축약을 하고, `resolveUniv` 가
`국립` 접두의 유무(입결은 `국립금오공대`처럼 붙여 쓰기도 한다)와
캠퍼스(`글로컬→글`, `ERICA→에`, `WISE→W`)를 가려 실제 이름을 고른다.
캠퍼스를 못 가리면 본교로 두고, 본교가 없으면 **포기한다**(null).

### 5.6b 결과 — **학생이 적고 선생님은 확인한다**

```js
resultOf(app)            // 즐겨찾기 값 위에 시트 값을 덮은 결과. pending 이 붙는다
setResult(app, next)     // 선생님이 적는다 (status='confirmed')
approveResult(app)       // 학생이 적은 것을 그대로 확인한다
pendingResults(cls)      // 확인을 기다리는 것 전부
// 학생 쪽: api 'studentResult' → status='student'
```

**121명 × 여섯 칸이면 700건이다.** 담임이 다 칠 수 없고, 애초에 합격자 발표는 학생이
대학 홈페이지에서 먼저 본다. 예비번호는 더 그렇다 — 학생은 하루에도 몇 번씩 본다.

그래서 **학생이 적고 선생님은 확인만 한다.** 선생님 화면의 주된 단추는 「맞습니다」다.

**고르는 말을 그대로 `final` 에 넣지 않는다.** 어느 칸에 무엇이 들어갈지는
`student.js` 의 `CHOICE` 표가 정한다.

| 학생이 고르는 말 | `final` | `stage1` | `enrolled` |
|---|---|---|---|
| 1단계 합격 | *(빈칸)* | 합격 | |
| 1단계 불합격 | *(빈칸)* | 불합격 | |
| 최초합격 | 최초합격 | | |
| 충원합격 | 충원합격 | | *(예비번호도 묻는다)* |
| 불합격 | 불합격 | | |
| 합격했지만 등록 안 함 | 최초합격 | | 미등록 |

「1단계 합격」을 `final` 에 넣으면 `stats.js` 가 **「합격」이라는 글자를 보고 최종
합격으로 센다.** 11월에 1단계만 난 건들이 지원 결과 보고서와 진학 대장에 부풀려
들어가고, 아무 데도 「틀렸다」고 안 적힌다. 「미등록」은 반대로 합격도 불합격도 아닌
값이 되어 통계에서 통째로 빠지고 「알아보지 못한 표기」 경고까지 뜬다 — 자기 화면이
준 선택지인데도.

`verdict()` 도 같은 것을 한 번 더 막는다. 화면이 안 그렇게 보내도 즐겨찾기가 최종 칸에
「1단계 합격」이라 적어 두거나 예전 값이 남아 있을 수 있다. 그리고 **「미등록」은
「등록」을 품고 있어서**, 글자로만 보면 안 간 학생이 등록한 것으로 세어진다.

- 학생 화면의 칸은 **셋뿐이다** — 결과 고르기 · 예비번호 · 저장.
  예비번호는 충원합격을 골랐을 때만 나온다. 늘 띄우면 여섯 칸이 다 예비번호 칸이 된다.
  「불합격 사유」는 학생이 모르고, 알아도 적기 괴로운 칸이라 선생님 쪽에만 둔다.
- 학생이 적은 것은 **바로** 선생님 화면에 뜨되 「학생이 적음」으로 표시된다.
  확인을 기다리다 대장이 비는 것보다 낫다.
- 칸별로 덮어쓴다 — 시트에 최종만 적었으면 1단계는 즐겨찾기 값이 그대로 남는다.
  **다만 최종 결과에 딸린 값(예비번호·불합격 사유·등록)은 따라 움직인다.** 칸마다
  「비었으면 즐겨찾기 것」을 하면, 최초합격으로 고친 뒤에도 옛 예비번호가 새어 나와
  「최초합격 · 예비 7번」이 되고 불합격이었던 건은 「최초합격 · 수능최저 미충족」이 된다.
- 즐겨찾기가 준 표기가 고르는 목록에 없으면 **그 표기도 목록에 넣는다.** 버리면 안 된다.

**담임이 무엇을 확인해야 하는지가 첫 화면에 있어야 한다.** 12월 아침에 보드를 여는
이유가 그것이다. 두 곳에 낸다 — 보드 맨 위의 「학생이 적은 결과 N건」 목록(누르면
그 카드가 바로 열린다)과 학생 명단의 배지. 명단은 **쓰기가 일어날 때도 다시 그린다.**
안 그러면 확인한 뒤에도 배지가 남아 같은 것을 두 번 연다.

진학 대장과 지원 결과 보고서도 `resultOf` 를 본다. 통계가 즐겨찾기만 보면
학생이 적어 둔 예비번호·등록이 빠진다.

### 5.6c 원서를 낸 뒤에 채워지는 칸 (`입력` 탭)

즐겨찾기에도 모집요강에도 없는 값이다 — 원서를 내고 **나서야** 알게 된다.
**학생이 적고 담임이 확인한다.** 면접 날짜와 같은 흐름이다.

| 칸 | 무엇 | 매인 곳 |
|---|---|---|
| `수험번호` | 원서를 내면 대학이 준다. 면접장에서 부르는 번호 | 지원 한 건 |
| `최종경쟁률` | 마감 뒤 대학이 발표한다. 예비번호가 얼마나 돌지 가늠할 때 | 지원 한 건 |
| `생년월일` | 합격 조회에 쓴다 | **학생 한 명** (id 는 빈 문자열) |

```js
store.fieldOf(app, '수험번호') · store.fieldOf(hak, '생년월일')
store.setField(app, field, value)      // 빈 값으로 부르면 지운다
store.approveField(app, field) · store.pendingFields(cls)
```

**메모 탭에 밀어 넣지 않는다.** 상담 메모가 묻히고, 칸을 더할 때마다 「접수번호 …」
같은 앞글자 규칙이 늘어난다. (접수번호는 이 구조를 만들기 전에 그렇게 들어갔다.)

**학생 화면에는 단계 단추가 없다.** 그래서 「접수번호가 적혔으면」으로 가른다 —
원서를 내야 받는 번호라 순서가 어긋날 수 없다. 9월에는 저절로 안 보이고, 원서를
내고 접수번호를 적는 순간 그 카드에만 나타난다. 「곧 있습니다」와 같은 방식이다.

생년월일은 지원마다 묻지 않는다. 화면 맨 아래에 한 번만, 그것도 지원 하나라도
접수번호가 적혔을 때만. 이미 적었으면 접힌 채로 둔다 — 자주 고칠 값이 아니다.

### 5.7 카드 위의 숫자 — 무엇을 두고 무엇을 빼나

```
작년 26입결        내 성적
70%컷  3.20   │   환산   2.94
실질   2.3:1  │   전교과 3.20
교과(일반)
```

- **대학 쪽과 학생 쪽을 가른다.** 셋을 한 줄에 늘어놓으면 70%컷·전교과·환산이
  같은 종류의 숫자로 읽힌다. 왼쪽은 대학이 작년에 어땠나, 오른쪽은 내가 어디에 있나다.
- **윗줄끼리 붙인다.** 70%컷과 대학 환산등급은 같은 잣대라 가로로 견줄 수 있다.
  전교과는 잣대가 달라 아랫줄에 참고로 둔다.
- **차이값은 계산하지 않는다.** 빼는 순간 자료가 말하지 않는 것을 말하게 된다.
- 경쟁률은 **실질을 먼저** 쓴다(모집요강 행의 72.7%에서 구해진다). 명목만으로는
  추합이 얼마나 돌았는지 안 보인다. 못 구하면 「경쟁률」이라 적고 명목을 쓴다.
- 제 입결이 없고 묶이기 전 선만 있으면 왼쪽이 「묶이기 전 참고」로 바뀌고
  가운데 선이 점선이 된다.
- **어느 전형의 컷인지 적는다.** 학과의 73% 는 입결에 전형이 여럿이라 「작년 26입결」
  만으로는 옆 전형의 컷과 구별이 안 된다. 교사 화면은 제목에 붙이고(이름으로 못 맞춘
  `cat`·`only` 는 아래에 드러내 놓는다), 학생 화면은 늘 아래 한 줄로 적는다.
- 지원한 전형을 못 가려냈으면(`typeFit === 'none'`) **비운다.** 「작년 컷 없음」과는
  다른 말이라 꼬리표도 다르다 — 교사는 「전형 못 가림」, 학생은 「작년 숫자 못 붙임」.
  카드 상세가 후보 전형 이름을 짚어 주고, 연도별 추이 표는 전형을 다 보여 준다.

꼬리표에 두는 것은 「이걸 모르면 상담에서 틀린 말을 하게 되는가」로 고른다.

**꼬리표 색은 넷뿐이다.** 늘어나면 아무 뜻도 없어진다.

| | 뜻 | 무엇 |
|---|---|---|
| `mark` 노란 칠 | **성적 말고 따로 걸리는 조건.** 놓치면 지원이 통째로 헛일이 된다 | 수능최저 · 단계별전형 · 가야 하는 날 |
| `warn` 붉은 글씨 | 진짜 문제 | 모집 반토막 · 자료 없음 · 올해 신설 · 전형 못 가림 |
| `wait` 점선 | 아직 확정이 아님 | 기간만 나온 날짜 · 불러오는 중 |
| (없음) | 참고 사실 | 모집인원 · 취업률 · 연계편입 · 결과 |

**카드 자체에 붙는 표시 둘.** 꼬리표로 달면 판단을 바꾸는 값들 옆에서 자리를 뺏는데,
이 둘은 그런 값이 아니라 훑을 때 걸려야 하는 자국이다.

| | | |
|---|---|---|
| 상담 메모 있음 | 왼쪽 얇은 띠 | 여섯 칸 중 어디를 이미 상담했는지 |
| 등록함 | 카드 전체를 두른 테두리 | 12월의 첫 물음이 「어디로 갔나」다 |

「미등록」은 「등록」을 품고 있어서 글자로만 보면 안 간 학생이 등록한 것으로 세어진다.
아닌 것을 먼저 걸러 낸 뒤에 맞는 것을 본다 — `stats.js` 의 `verdict` 과 같은 규칙이다.
학생 화면의 「이 학교로 갑니다」도 같다. 「불합격」이 「합격」을 품고 있어서, 안 걸러
내면 떨어진 칸에도 등록 물음이 뜬다.

셋이 같은 무게다 — 수능최저·단계별전형·가야 하는 날. 내신이 닿아도 최저에서
떨어지고, 1단계를 따로 통과해야 하고, 그날 못 가면 끝난다. 「연계편입」은 혜택이지
걸리는 조건이 아니라 노란 칠에서 뺐다.

**판단을 줄인 말은 꼬리표에 두지 않는다.** 「많이 흔들림」은 사실이 아니라 읽는
법이다 —「최근 5년 사이 2.96~4.50 으로 1.54등급 움직였습니다」를 한 낱말로 줄인
것인데, 옆의 「30명」·「면접 9/4」와 나란히 놓이면 같은 무게의 사실로 읽힌다.
근거와 붙어 있어야 하므로 상세의 「이 컷을 어떻게 읽나」로 옮겼다.

### 단계 — 지원 고민 ↔ 지원 확정 (`body[data-stage]`)

9월에 여섯 칸을 고를 때와 원서를 낸 뒤에 보는 것이 다르다. 단추 하나로 가른다.

| | 지원 고민 | 지원 확정 |
|---|---|---|
| 결과 꼬리표 (합불·예비) | 안 낸다 | 낸다 |
| 후보 · 보관 묶음 | 편다 | **접는다** (지우지 않는다) |
| 전문대 · 특수대 묶음 | 편다 | 편다 — 6회 제한 밖이라 12월에도 살아 있다 |

단계를 바꿔도 **보던 화면에 그대로 둔다.** 처음 열 때만 어느 화면으로 갈지 정한다 —
보드에서 결과를 보려고 눌렀는데 일정판으로 끌려가면 다시 돌아와야 한다.

`data-stage` 는 예전에 `<body>` 에 적히기만 하고 **읽는 데가 없었다.** 단추가 탭만
바꾸고 화면은 그대로였다. 지금은 `MutationObserver` 가 보고 카드를 다시 그린다.

접힌 묶음도 끌어다 놓을 수 있어야 한다 — 끌고 오면 펴진다.

| 두는 것 | 이유 |
| --- | --- |
| 모집인원 증감 | 30명이 3명이 되면 작년 컷은 더 이상 쓸 수 없다 |
| 단계별 전형 | 1단계를 따로 통과해야 한다. 최종 컷만 보면 안 된다 |
| 수능최저 | 내신이 닿아도 최저에서 떨어진다 |
| 가야 하는 날 | 면접·실기·논술은 겹치면 하나를 버려야 한다 |
| 연결 상태 | 값이 왜 비었는지 감추지 않는다 |

지역·계열·모집시기·50%컷·취업률은 두지 않는다. 상세에서 본다.
붉은 꼬리표는 **모집인원이 3명 이상이면서 20% 넘게 줄었을 때만** 쓴다.
두어 명 줄어든 것까지 붉게 칠하면 정작 반 토막 난 전형이 눈에 안 들어온다.

교사 화면과 학생 화면은 `summarize()` 하나를 같이 본다. 같은 지원이 두 화면에서
다른 숫자로 보이면 안 된다.

### 5.8 `board/stats.js` · `board/export.js` — 내보내기 (P7)

```js
// stats.js — 순수 함수. 화면을 모른다.
verdict(app)        // → {decided, passed, extra, stage1Out, minFail, enrolled, raw}
typeOf(app)         // '교과' | '종합' | '논술' | '실기' | '기타'
overall(rows)       // 전체 현황
byUniv(rows, n)     // 대학별 · 전형별 지원/합격/평균/최고/커트
byType(rows)        // 전형별 합격률 · 충원율 · 1단계 탈락
gyoVsJong(rows, k)  // 같은 대학 안에서 교과와 종합
minFails(rows)      // 수능최저 미충족
byBand(rows)        // 등급대별로 실제 어디에 붙었나
report(rows, opts)  // 위를 한 판으로
```

`rows` 는 `[{app, student}]` 다. 순수 함수라 `board/stats.test.mjs` 가 지어낸 자료로 검사한다.

**결과 표기는 대교협이 주는 대로**라 해마다 조금씩 다르다. 그래서 아는 말만 골라 세고
**모르는 값은 `unknown` 으로 돌려준다.** 화면이 그걸 띄워야 숫자가 왜 안 맞는지 알 수 있다.
모르는 값을 합격으로도 불합격으로도 세지 않는다.

지켜야 할 것 몇 가지 —

- **「커트」는 합격자 중 가장 낮은 등급(최댓값), 「최고」는 가장 좋은 등급(최솟값)** 이다.
  등급은 작을수록 좋으므로 여기서 뒤집으면 표 전체가 뒤집힌다. 시험이 이걸 지킨다.
- **교과와 종합은 같은 대학 안에서만 견준다.** 전체 평균으로 견주면 「종합이 더 높은
  성적을 요구한다」는 잘못된 결론이 나온다 — 종합으로 상위권에 더 많이 넣기 때문이다.
- **충원합격은 `final` 에 「충원·추가」가 있거나 예비번호가 있을 때**로 본다.
- **1단계 탈락은 최종과 따로 센다.** 종합에서 서류로 떨어지는 것이 별개의 관문이다.
- 등급대 구간은 `[lo, hi)` — 아래를 포함하고 위를 뺀다. 3.0 은 3~4등급대다.

`export.js` 는 그걸 그린다. 화면과 종이가 **같은 값**을 본다.

| 나가는 길 | 무엇 |
|---|---|
| 인쇄 (A4) | 대장은 학생 한 명이 한 쪽. 보고서는 이어서 |
| 표 복사 | 탭으로 나눈 글. 한글·엑셀에 붙이면 **표로** 들어간다 |
| CSV | 원자료. 엑셀이 한글을 깨지 않도록 BOM 을 붙인다 |

한글(HWPX)로 바로 뽑지는 못한다 — 브라우저가 만들 수 있는 형식이 아니다.
「표 복사」가 그 자리를 메운다.

인쇄에서 지키는 것 —

- `.sheet` 하나가 한 쪽(`break-after: page`). 마지막 장은 빈 쪽을 만들지 않는다.
- `thead { display: table-header-group }` — 쪽이 넘어가도 표 머리가 따라간다.
- 대장 표는 열이 열한 개라 `table-layout: fixed` + `colgroup` 으로 너비를 정한다.
  안 정하면 A4 세로에서 「건국대학 / 교(서울)」처럼 대학 이름이 가운데서 끊긴다.
- 왼쪽 학생 명단(`.layout > aside`)은 종이에 싣지 않는다. 화면을 옮겨 다니는 도구다.
- 1단계는 **떨어졌을 때만** 적는다. 통과까지 적으면 「합격 · 불합격」이 되어 읽히지 않는다.

### 5.9 `board/verify.js` — 점검 (P8)

```js
// store.js
unmatched(cls)                       // 못 붙인 것을 (대학·학과)끼리 묶어서
candidatesFor(app, n)                // 같은 대학의 닮은 학과. 고르지는 않는다
aliasOf(app)                         // 이 지원에 걸린 별칭
setAlias(univ, dept, toUniv, toDept, note)
removeAlias(univ, dept)

// match.js
similarity(a, b)                     // 0 ~ 1
candidates(app, src, n)              // → [{dept, score, years, kind}]
```

**자동으로 잇지 않는다.** 「화학공학과」와 「화공생명공학과」는 글자가 거의 안 겹치는데
같은 학과일 수 있고, 「영어영문학과」와 「영어교육과」는 닮았는데 전혀 다른 학과다.
기계가 고르면 반드시 몇 개를 틀리고, **틀린 값은 화면 어디에도 「틀렸다」고 안 적힌다.**
그래서 후보를 점수와 함께 늘어놓고 사람이 고른다.

`similarity` 는 두 값을 섞는다.

    0.6 × 두 글자씩 끊어 겹치는 정도 (bigram dice)
  + 0.4 × 낱글자로 겹치는 정도       (character dice)
  + 0.15 (한쪽이 다른 쪽을 통째로 품으면)

낱글자 항을 넣은 이유 — 「화공생명공학과」와 「생명화학공학과」는 같은 학과인데 글자
**차례**가 달라 두 글자씩 끊어 보면 거의 안 겹친다. 낱글자로 보면 넷 중 넷이 겹친다.
이 항이 없으면 정답이 4위로 밀리고 엉뚱한 「생명과학과」가 1위가 된다. 시험이 이걸 지킨다.

**학과를 여럿 이을 수 있다.** 자유전공·통합모집은 작년의 한 학과에 대응하지 않는다 —
「자유전공학부」의 작년 자리를 물으면 답이 「경영 · 경제 · 행정」 셋인 식이다. 하나만
고르게 하면 셋 중 아무거나 골라 그 값을 이 학과의 값인 양 달게 된다.

`toDept` 에 쉼표로 여럿을 적으면 **이름을 바꾸지 않고** 모집요강이 주는 「묶이기 전
학과」와 같은 자리에 같은 꼴로 낸다 — 범위·가운데값·학과별 값. 점검 화면에서 후보를
여럿 눌러 고른다. 하나만 고르면 예전처럼 그 이름으로 바꿔 붙인다.

**별칭은 학생이 아니라 학과에 붙는다** (`별칭` 탭, 키는 `univ|dept`).
그래서 엑셀 원본을 갈아끼워도, 다음 해가 와도 그대로 남는다.
`link()` 이 붙일 때만 이름을 바꿔 쓰고, 화면에는 학생이 넣은 원래 이름이 나온다.

「목록 복사」는 못 붙인 목록을 글로 내준다 — 그대로 Claude 에게 붙여 넣고 물어보라는
용도다. **학생 이름은 넣지 않는다.** 밖으로 나가는 글이고, 학과 이름을 맞추는 데
학생이 누구인지는 필요 없다.

### 5.10 `board/confidence.js` — 얼마나 믿을 수 있나

```js
swing(rows, type, norm)          // 연도별 70%컷 → {n, years, lo, hi, span, sd, slope, r2, direction}
thinness(quota)                  // 모집인원으로 본 흔들림
position(mine, c50, c70)         // 두 컷 **사이일 때만** 위치를 말한다
confidence(summary, mine, norm)  // → {level, label, evidence, lack, why, trend, ...}
worthFlagging(c)                 // 카드 꼬리표를 붙일 만한가
```

`confidence` 는 `summary.mine` — **지원한 전형의 줄만** 본다. 못 가려냈으면
`null` 을 돌려준다. 옆 전형의 변동폭을 빌려 오면 그럴듯하게 틀린다.
`norm` 은 `match.js` 의 `normType` 이다. 글자 그대로 견주면 `종합(고교생활Ⅰ)` 과
`종합(고교Ⅰ)` 이 갈려 「견줄 해가 한 해뿐」이 되어 버린다.

```js
percentile(rows, mine)     // → {pct, mu, sd, years, weak}  작년 합격자 분포에서 내 자리
predictCut(rows)           // → {center, lo, hi, sigma, vola, rebound, n}  올해 컷은 범위로
stance(pct, vola)          // → {key, label, shaky}  안정 · 적정 · 소신 · 상향
pctText(pct)               // 양 끝은 숫자로 읽히면 안 되므로 말로 바꾼다
```

**센 값과 어림한 값을 갈라 놓는다.** 위 넷은 근사다 — 두 분위점으로 분포를
가정해서 낸다. 화면에서도 왼쪽 선으로 구역을 나누고 「어림해 보면」이라 적는다.
근거(견준 해·움직인 폭·모집인원)를 **먼저**, 어림을 **나중에** 놓는다. 판정을 먼저
보면 그 아래 숫자를 판정의 뒷받침으로 읽게 된다.

식·문턱·한계 문구는 `counsel.html` 과 같아야 한다. 한쪽을 고치면 다른 쪽도 고친다.
자세한 것은 `ARCHITECTURE.md` §6.

**유의검정(p값·신뢰구간)은 하지 않는다.** 입결은 대학이 공개한 요약값이라 합격자
개개인의 점수가 없다. 개별 값이 없으면 분산을 모르고, 분산을 모르면 검정도 신뢰구간도
만들 수 없다. 그 자리에 숫자를 놓으면 계산이 아니라 지어내기다. 화면에도 그렇게 적는다.

대신 정말 셀 수 있는 것 넷 — 해마다 얼마나 움직였나 · 몇 명을 뽑나 · 어느 쪽으로
가고 있나 · 내 점수가 어디쯤인가.

**문턱은 짐작이 아니라 자료를 재서 잡았다.** (`data/ipgyeol.json` 의 13,948 조합)

| | 분포 | 잡은 문턱 |
|---|---|---|
| 움직인 폭 | 중앙 0.54 · 75% 0.98 · 90% 1.49 | 많이 흔들림 1.5 · 흔들림 1.0 |
| 모집인원 | 5명 이하 32% · 15명 이하 76% | 경고는 3명 이하만 |
| 기울기 | — | 해마다 0.1등급 넘고 R² 0.5 넘을 때만 「흐름」 |

처음에 폭 0.5 를 흔들림으로 잡았더니 절반이 걸렸고, 모집 15명 이하를 경고했더니 넷 중
셋이 걸렸다. **흔한 것을 경고하면 경고가 사라진다.**

**「흔들린다」와 「모른다」를 가른다.** 그 전형의 입결이 한 해치뿐인 경우가 61% 다.
불안정한 게 아니라 아직 모르는 것이다. `level` 은 잰 흔들림만 담고, 자료가 얼마나
있는지는 `evidence` 에 따로 둔다. 카드 꼬리표는 `level` 만 본다(21.6% 에 붙는다).
못 쟀는데 「안정적」이라 적지 않고 「알 수 없음」이라 적는다.

**내 위치는 두 컷 사이일 때만** 말한다. 밖이면 「밖」이라고만 적고 숫자를 만들지 않는다 —
두 점으로 바깥을 늘려 재는 건 자료가 하지 않은 말이다.

## 6. 지켜야 할 것

- **못 붙인 것을 숨기지 않는다.** 추측으로 값을 채우느니 「연결 안 됨」이 낫다.
- **원문을 버리지 않는다.** 파싱에 실패한 값은 `unknown` 에 남겨 화면에 띄운다.
- **6칸을 조용히 넘기지 않는다.** 7번째를 놓으면 무엇을 뺄지 묻는다.
- **집계를 조용히 추측하지 않는다.** 전형유형이 `학생부위주` 로만 찍혀 갈리지 않으면
  내보내기를 막고 물어본다.
- 모든 사용자용 문장은 한국어. 단정할 수 없으면 단정하지 않는다.
- **어느 탭을 읽었는지 밝힌다.** 원본 탭 이름이 아는 것과 다르면 첫 탭을 읽되
  그렇다고 화면에 적는다. 조용히 읽고 「학생 0명」만 뜨면 왜 비었는지 알 길이 없다.
- **닮았다고 잇지 않는다.** 후보를 점수와 함께 보여 주고 사람이 고른다.
- **유의검정을 흉내 내지 않는다.** 개별 합격자 점수가 없는 자료로 p값을 적으면
  계산이 아니라 지어내기다.
- **문턱은 자료를 재서 잡는다.** 흔한 것을 경고하면 경고가 사라진다.
- **자료 쪽 표기를 글자 그대로 믿지 않는다.** `학교유형` 이 「대학교」·「전문대학」
  처럼 아는 말과 조금만 달라도 예전에는 그 학생의 여섯 칸이 통째로 미연결이 되고
  「대학교는 입결 자료가 없습니다」라는 알 수 없는 말만 떴다. `univKind()` 가 셋 중
  하나로 줄이고, **못 알아본 것은 못 알아봤다고 두어** 두 자료를 다 뒤진다.
- **학과까지만 맞추고 전형을 아무 줄이나 쓰지 않는다.** 입결은 (대학·학과)로만 묶여
  있고 학과의 73% 에 전형이 여럿이다. 못 가리면 비운다.
- **끌어다 놓는 곳은 여섯 칸만이 아니다.** 후보·보관 묶음도 집는 곳이자 놓는 곳이다
  (`dragSource` · `dropTarget`). 여섯 칸에서만 되면 「일단 후보로 빼 두기」가 안 된다.
  전문대를 여섯 칸에, 일반대를 전문대 묶음에 놓는 것은 막는다.
